# Контакт — личная база клиентов

Приложение для Влада: компании и потенциальные клиенты, семь статусов, все 18 исходных полей анкеты, логотип или фото ИП, инициалы и сведения о последнем созвоне.

## Как работать
1. Нажмите «Добавить клиента» и заполните название.
2. Укажите статус, ассортимент, потенциал, аргументы, контакты и следующий шаг.
3. Нажмите «Сохранить карточку». Изменения хранятся в серверной базе.
4. Выбирайте статус слева, пользуйтесь поиском и фильтрами. На телефоне статус выбирается в выпадающем списке.
5. Откройте компанию для редактирования. Удаление требует подтверждения.
6. Загрузите JPG, PNG или WebP до 5 МБ. Для логотипа сохраняется всё изображение; фото ИП заполняет миниатюру. Замену и удаление подтвердите кнопкой «Сохранить карточку».
7. Инициалы / имя ИП сохраняются независимо от фото; при отсутствии изображения показывается буквенная миниатюра.
8. Укажите дату последнего созвона и комментарий. В списке дата отображается как ДД.ММ.ГГГГ.
9. Выберите «Сначала давние звонки» или «Сначала недавние звонки». Записи без даты остаются в конце. Фильтр «Без созвона» сочетается с поиском, статусом, потенциалом и типом бизнеса.

Статусы назначаются вручную. «Новый» — одна оплата за последние 6 месяцев; «Постоянный» — несколько оплат за этот период. Приложение не подключено к учётной системе и не рассчитывает оплаты автоматически.

База изначально пустая: вымышленные компании не добавлены. Сайт компании фиксируется как URL; автоматический анализ сайта не включён в эту версию.

## Техническая структура
- React / Vinext, Cloudflare Worker, D1 для анкет и приватный R2 для изображений.
- `app/workspace.tsx`: интерфейс.
- `lib/client-model.ts`: исходные поля, сведения о созвонах, статусы, серверная проверка входных данных и сортировка календарных дат.
- `app/api/clients/route.ts`: CRUD; записи изолированы по идентификатору пользователя.
- `app/api/clients/photo/route.ts`, `lib/client-photos.ts`: загрузка и выдача изображений с проверкой владельца, формата и размера.
- `db/schema.ts`, `drizzle/`: исходная схема; новые поля добавлены в JSON анкеты без удаления или пересоздания таблиц.
- `.openai/hosting.json`: идентификатор приложения, логическая привязка DB.
- Приватный доступ обеспечивается платформой. В API обязателен подтверждённый платформой пользователь.

## Проверка
`node tests/run-local.mjs` запускает локальный сервер и интеграционные сценарии с D1/R2. Используется отдельная тестовая учётная запись; созданные тестовые записи удаляются в конце. Перед первым запуском примените исходную миграцию к локальной D1. Тесты не допускают адрес рабочей базы.

Проверяются сохранение всех 18 прежних полей, фото и инициалов, повторное независимое чтение, JPG/PNG/WebP, замена и удаление изображения, отклонение файлов больше 5 МБ и неподдерживаемого содержимого, сохранность данных при ошибке, редактирование и очистка даты/комментария, обе сортировки с пустыми датами в конце, комбинации фильтров, семь статусов, обязательный вход и изоляция владельцев.

Проверяются TypeScript, ESLint изменённых модулей и production-сборка. Серверные и браузерные проверки описываются отдельно: успешный API-тест сам по себе не подтверждает проверку интерфейса на физическом телефоне.

## Запуск для разработки
Установите зависимости из lockfile; используйте `pnpm dev`. Настройте D1 и доверенную платформенную авторизацию. Для миграций: `pnpm db:generate`. Для сборки: `pnpm build`. Нельзя доверять заголовкам пользователя при размещении вне доверенного шлюза авторизации.

Копия исходников в Google Drive не является резервной копией клиентских записей. Автоматической синхронизации данных с Google Drive или GitHub нет.
