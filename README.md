# Контакт — личная база клиентов

Приложение для Влада: компании и потенциальные клиенты, семь статусов, все 18 исходных полей анкеты, логотип или фото ИП, инициалы и сведения о последнем созвоне.

## Как работать
1. Нажмите «Добавить клиента» и заполните название.
2. Укажите статус, ассортимент, потенциал, аргументы, контакты и следующий шаг.
3. Нажмите «Сохранить карточку». Изменения хранятся в серверной базе.
4. Выбирайте статус слева, пользуйтесь поиском и фильтрами. На телефоне статус выбирается в выпадающем списке.
5. Откройте компанию для редактирования. Удаление требует подтверждения.
6. Загрузите JPG, PNG или WebP до 5 МБ. Для логотипа сохраняется всё изображение; фото ИП заполняет миниатюру. Замену и удаление подтвердите кнопкой «Сохранить карточку».
7. Инициалы / имя ИП сохраняются независимо от фото; при отсутствии изображения показывается буквенная миниатюра.
8. Укажите дату последнего созвона и комментарий. В списке дата отображается как ДД.ММ.ГГГГ.
9. Выберите «Сначала давние звонки» или «Сначала недавние звонки». Записи без даты остаются в конце. Фильтр «Без созвона» сочетается с поиском, статусом, потенциалом и типом бизнеса.

Статусы назначаются вручную. «Новый» — одна оплата за последние 6 месяцев; «Постоянный» — несколько оплат за этот период. Приложение не подключено к учётной системе и не рассчитывает оплаты автоматически.

База изначально пустая: вымышленные компании не добавлены. Сайт компании фиксируется как URL; автоматический анализ сайта не включён в эту версию.

## Техническая структура
- React / Vinext, Cloudflare Worker, D1 для анкет и приватный R2 для изображений.
- `app/workspace.tsx`: интерфейс.
- `lib/client-model.ts`: исходные поля, сведения о созвонах, статусы, серверная проверка входных данных и сортировка календарных дат.
- `app/api/clients/route.ts`: CRUD; записи изолированы по идентификатору пользователя.
- `app/api/clients/photo/route.ts`, `lib/client-photos.ts`: загрузка и выдача изображений с проверкой владельца, формата и размера.
- `db/schema.ts`, `drizzle/`: исходная схема; новые поля добавлены в JSON анкеты без удаления или пересоздания таблиц.
- `.openai/hosting.json`: идентификатор приложения, логические привязки DB и BUCKET; никаких секретов.
- Доступ к API и фото обеспечивается серверной сессией по коду доступа. Заголовки пользователя ChatGPT не используются.

## Проверка
После `pnpm build` команда `node tests/run-local.mjs` запускает собранный Worker с отдельными временными D1/R2, сама применяет все миграции и генерирует случайные тестовые секреты. Запускаются unit-тесты сессий и интеграционные сценарии авторизации/анкет/фото. Временные данные удаляются в конце. Рабочая база не используется.

Проверяются сохранение всех 18 прежних полей, фото и инициалов, повторное независимое чтение, JPG/PNG/WebP, замена и удаление изображения, отклонение файлов больше 5 МБ и неподдерживаемого содержимого, сохранность данных при ошибке, редактирование и очистка даты/комментария, обе сортировки с пустыми датами в конце, комбинации фильтров, семь статусов, обязательный вход и изоляция владельцев.

Проверяются TypeScript, ESLint изменённых модулей и production-сборка. Серверные и браузерные проверки описываются отдельно: успешный API-тест сам по себе не подтверждает проверку интерфейса на физическом телефоне.

## Запуск для разработки
Установите зависимости из lockfile; используйте `pnpm dev`. Настройте локальные D1/R2 и секреты в игнорируемом `.dev.vars` (никогда не коммитьте его). Для миграций: `pnpm db:generate`. Для сборки: `pnpm build`. Приложение не доверяет заголовкам `oai-authenticated-user-*`.

Копия исходников в Google Drive не является резервной копией клиентских записей. Автоматической синхронизации данных с Google Drive или GitHub нет.


## Вход по кодам доступа

Регистрации и внешнего сервиса авторизации нет. Введите личный код на стартовом экране; кнопка «Выйти» удаляет cookie из браузера. Код не хранится в localStorage/IndexedDB и не попадает в клиентский bundle.

Секреты доступны серверу через `import { env } from 'cloudflare:workers'`, как существующие bindings `DB` и `BUCKET`. `app/session.ts` связывает окружение с независимым модулем Web Crypto `app/session-core.ts`. Адаптер `getChatGPTUser(request)` сохраняет формат `{ userId, displayName, email, fullName }`: displayName равен userId, email пустой, fullName null. Источник идентификатора — только проверенная cookie.

### Секреты

- `ACCESS_CODES`: `userId:код,userId2:код2`. Пример структуры с заполнителями: `vlad:<ВАШ_СЛУЧАЙНЫЙ_КОД>,manager2:<ДРУГОЙ_КОД>`. Заполнители нужно заменить, это не готовые коды. Для каждого человека задайте уникальный userId и уникальный случайный код длиной 12–256 символов. В коде нельзя использовать запятую, двоеточие и управляющие символы. Не используйте короткий цифровой PIN. Пробелы в кодах значимы; после запятых их добавлять не нужно. userId — до 200 символов, без пробелов, запятых и двоеточий.
- `SESSION_SECRET`: случайный секрет минимум 32 байта, например результат `openssl rand -hex 32`. Храните его отдельно от кодов; не присылайте его в публичный репозиторий.

**Для этого проекта в Sites:** в настройках окружения выбранного сайта задайте `ACCESS_CODES` и `SESSION_SECRET` как секреты (оба `is_secret: true` при работе через Sites connector `update_environment_variables`). После изменения окружения нужно опубликовать сохранённую версию: новая ревизия окружения применяется при deployment. Секреты не помещаются в `.openai/hosting.json`. Если в интерфейсе нет управления секретами, используйте подключённый Sites, а не GitHub.

**При самостоятельном размещении в своём Cloudflare аккаунте:** после настройки Wrangler на ваш реальный Worker выполните интерактивно:

```sh
pnpm exec wrangler secret put ACCESS_CODES --name <ИМЯ_ВАШЕГО_WORKER>
pnpm exec wrangler secret put SESSION_SECRET --name <ИМЯ_ВАШЕГО_WORKER>
```

Wrangler запросит значения отдельно. Эти команды требуют доступа к Cloudflare аккаунту владельца Worker; они не заменяют настройки управляемого Sites. Сгенерированный локально `dist/server/wrangler.json` содержит тестовые идентификаторы D1 и не является конфигурацией для самостоятельного production-развёртывания. Документация: https://developers.cloudflare.com/workers/configuration/secrets/

### Добавление, отзыв и разделение пользователей

Добавление человека: добавьте новую пару в `ACCESS_CODES`, сохранив прежние, и примените новое окружение публикацией. Разные userId имеют разные базы. Не выдавайте одинаковый userId разным людям, если не хотите дать доступ к одной базе.

Отзыв: удалите пару из `ACCESS_CODES` и примените окружение. Проверка текущего списка выполняется при каждом запросе: ранее выданная cookie этого пользователя сразу перестаёт работать после применения конфигурации. Смена его кода также отзывает его cookie. Смена `SESSION_SECRET` отзывает все сессии. Пустой `ACCESS_CODES` отзывает всех. Ошибка конфигурации закрывает доступ; резервного входа через ChatGPT нет. Сам выход очищает cookie конкретного браузера, но не отзывает её копию на другом устройстве: для этого смените код.

### Существующая база

Владелец записи хранится в `clients.owner`, раньше туда записывался заголовок `oai-authenticated-user-id`. Для сохранения доступа укажите в `ACCESS_CODES` **точное прежнее значение `owner`**, включая регистр; переименование в `vlad` не переносит записи автоматически. Проверить владельцев можно в консоли D1:

```sql
SELECT owner, COUNT(*) AS records FROM clients GROUP BY owner;
```

При проверке рабочей таблицы выбранного сайта 01.10.2026 она была пустой (0 строк). Поэтому значение старого owner не установлено; для новой базы допустим userId `vlad`. ID владельца проекта Sites не подставляется вместо owner: это другой идентификатор. Таблица клиентов и объекты R2 при смене авторизации не меняются.

### Защита и ограничения

Cookie `session`: HMAC-SHA256, срок 30 дней без автоматического продления, HttpOnly, Secure, SameSite=Lax, Path=/, без Domain. Подписи и коды сравниваются через нативную проверку HMAC Web Crypto; цикл проверяет все коды без раннего выхода. Cookie содержит userId, срок и HMAC версии кода, но не сам код. Только HTTPS в рабочем окружении.

Лимит — пять неверных попыток за фиксированное окно 10 минут с одного IP. Таблица D1 `login_attempts` выбрана вместо памяти Worker, потому что память не общая между экземплярами и теряется при перезапуске. Атомарное резервирование слота защищает от параллельных запросов; успешная попытка освобождает свой слот, но не стирает предыдущие ошибки. Пять одновременных запросов занимают слоты до завершения. 401 для неверного кода с задержкой 1,2–1,8 секунды; после исчерпания лимита — 429 и Retry-After. Люди за одним IP делят лимит. IP берётся только из установленного Cloudflare заголовка `CF-Connecting-IP`, в D1 хранится его HMAC. Если заголовка нет, используется общий лимит. Развёртывайте за доверенным Cloudflare edge, не доверяйте клиентскому X-Forwarded-For. Истёкшие записи очищаются при следующих попытках входа.

Миграция `drizzle/0001_tricky_kid_colt.sql` добавляет только таблицу счётчика и индекс. Sites применяет её при публикации. При своём Cloudflare размещении примените миграции к нужной D1 до запуска нового кода; старую миграцию 0000 повторно вручную не выполняйте. Запросы изменения проверяют Origin; вход принимает только ограниченный по размеру JSON; API и фото возвращают 401 без сессии. Фото и данные получают Cache-Control: no-store.

Для работы без ChatGPT внешняя политика Sites должна разрешать анонимно открыть страницу входа (`public`), а доступ к данным ограничивает приложение. При проверке 01.10.2026 сайт уже имел `public`; настройка не изменялась. Наличие исходников в публичном GitHub не даёт доступа к базе.

### Проверки перед публикацией

```sh
pnpm exec tsc --noEmit --incremental false
pnpm build
node tests/run-local.mjs
```

Тесты покрывают верный/неверный код, истёкшую/подделанную cookie, отзыв и смену кодов/секрета, отсутствие сессии (в том числе при поддельных заголовках ChatGPT), выход, Origin, ограничение попыток и параллельных входов, разделение чтения/редактирования/удаления/фото двух пользователей и прежние функции анкет.

Новая авторизация требует задания production-секретов перед переключением сайта. Тестовые секреты никогда не используются в рабочем окружении.
